Твой компьютер общается с сотнями серверов в день. На Linux классические ответы — `tcpdump`, `ss`, `netstat` или Wireshark — мощные, но они отвечают на «покажи пакеты», а не на «с кем говорит моя машина, и стоит ли волноваться?».

Я написал [Snitch](https://github.com/aixisstudio/Snitch) именно для второго вопроса — open-source визуализатор сети в реальном времени (AGPL), полностью работающий на Linux через Docker или релизный бинарь. Честно: я автор, так что вот трезвый обзор существующего и места Snitch.

## Ландшафт Linux

| Инструмент | Что делает | Чего не делает |
|---|---|---|
| **tcpdump / ss / netstat** | Сырые данные о соединениях | Без UI, истории, геолокации, привязки к приложениям |
| **Wireshark** | Глубокая диссекция пакетов | Перебор для «кто стучит домой» — микроскоп, не дашборд |
| **OpenSnitch** | Фаервол приложений (промпты block/allow) | Минимальная визуализация — block-first, только Linux |
| **iftop / nethogs / nload** | Bandwidth по интерфейсу или процессу | Без карты мира, детекта аномалий, персистентности |
| **Snitch** | Живая карта каждого соединения: приложение → сервер → страна, детект аномалий, история 24 ч, opt-in блокировка через фаервол ОС | Применение правил ОС — best-effort (нужны привилегии); не полный интерактивный фаервол |

OpenSnitch и Snitch — комплементарны, не конкуренты: OpenSnitch — зрелый интерактивный фаервол приложений, Snitch показывает, *что* делает твоя машина — и с v1.2 ещё может пушить правила (`ip`/`cidr`/`domain`/`process`/`port`) в `iptables` плюс переключатель lockdown, best-effort.

## Что Snitch даёт на Linux

- **Живая карта мира** каждого исходящего соединения с атрибуцией процесса — какое приложение его открыло, а не просто IP
- **Офлайн-геолокация** через локальную базу MaxMind/DB-IP — твои IP не покидают машину
- **Детект аномалий**: port-сканы в LAN, beaconing (регулярные колбэки — классический паттерн C2), необычный исходящий объём, DNS-туннелирование, отклонения от baseline по процессам
- **Privacy score** + детект трекеров по редактируемым спискам суффиксов
- **Bandwidth по приложениям**, таймлайн, хранение SQLite 24 ч, правила подавления тревог
- **Пассивный LAN-скан** через системную ARP-таблицу — все устройства сети, без единого инъецированного пакета
- **Исходящие правила фаервола + lockdown** — блок IP, CIDR, домена, процесса или порта через нативный фаервол (`iptables` на Linux), kill/suspend процессов, форензик-бандл (JSON/CSV/STIX)
- **Opt-in threat intel** — репутация через AbuseIPDB / AlienVault OTX / VirusTotal с твоим ключом API
- UI и доки на 8 языках (EN/FR/ES/DE/RU/JA/PT-BR/中文)

## Часть про приватность

Это первое, что проверяют линуксоиды, поэтому: API биндится на **127.0.0.1** и требует токен. **Ни телеметрии, ни аккаунта**, а каждый исходящий вызов — загрузка GeoIP, проверки обновлений, threat intel, вебхуки — независимо opt-in. Данные о трафике живут в локальном файле SQLite, принадлежащем тебе.

## Установка

```bash
# Docker (для захвата нужен host networking)
docker run --network host ghcr.io/aixisstudio/snitch

# или релизный tarball — нужен root/cap_net_raw как у tcpdump
sudo ./snitch-backend
```

Затем открой напечатанный URL. Есть и демо-режим (`SNITCH_DEMO=1`), гоняющий синтетический трафик через настоящий конвейер — посмотреть до выдачи прав захвата.

## Что под капотом (для любопытных)

Чистый Python + ctypes → libpcap для захвата — без Scapy. Парсинг IPv4/IPv6/TCP/UDP/DNS/TLS-SNI написан вручную, ~2K строк на весь конвейер. Бэкенд FastAPI + WebSocket, фронтенд React + D3, оболочка Electron на десктопе.

Если хочешь ответ на «не болтает ли моя машина со странными местами в 3 часа ночи» на Linux — без платного фаервола и круглосуточного сниффинга — это ровно оно. ⭐ на [GitHub](https://github.com/aixisstudio/Snitch), если заслужил, и в Discussions есть тред «что вы поймали?» — буду рад скриншотам.
