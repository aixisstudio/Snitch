# Privacy Score — Методология

[English](privacy-score.md) | [Français](privacy-score.md) | [Español](privacy-score.es.md) | [Deutsch](privacy-score.de.md) | **Русский** | [日本語](privacy-score.ja.md) | [Português](privacy-score.pt-BR.md) | [中文](privacy-score.zh-CN.md)

Оценка (A–F, справа вверху) вычисляется в
`frontend/src/scoring/privacy.js` из живого состояния
узлов/рёбер/тревог. Это **эвристика**, а не формальная гарантия —
опишите свою модель угроз, прежде чем полагаться на букву.

Входы и веса:

| Сигнал | Эффект |
|---|---|
| Узлы категории трекеров (известные ad/analytics-домены по DNS/SNI) | −8 очков каждый |
| Тревоги `critical`/`warning` в окне | −10 / −4 очка каждая |
| Доля байтов к пунктам, помеченным как трекеры | пропорциональный штраф |
| Число различных удалённых хостов | мягкий штраф свыше ~30 |
| Доля HTTPS (трафик порта 443) | небольшой бонус |

Известные ограничения:

- Сопоставление трекеров опирается только на наблюдаемые имена DNS/SNI —
  трекер по «голому» IP не совпадёт. Это намеренно (нет сопоставления по
  подстроке в обратном PTR, которое давало ложные срабатывания типа
  `notfacebook.com`).
- Буква A–F — порядковое резюме, а не измерение. Читайте её как тренд,
  а не как абсолютное значение.
