Твой компьютер прямо сейчас разговаривает с интернетом. Вероятно, десятки соединений — синхронизация, телеметрия, проверки обновлений, открытые вкладки, фоновая болтовня приложений. Вопрос «что на самом деле делает моя машина?» звучит просто, но попробуй на него ответить — и обнаружишь, что инструменты либо микроскопические (Wireshark), либо за пейволом.

Вот практический гид, как это реально увидеть — включая инструмент, который я для этого написал, [Snitch](https://github.com/aixisstudio/Snitch) (open source, AGPL — честно, он мой).

## Версия за 60 секунд

```bash
# macOS / Linux — классика, но сыро
sudo tcpdump -i any -n | head -50        # каждый пакет, без контекста
netstat -anp tcp | grep ESTABLISHED      # только текущие соединения
lsof -i -nP | head                       # маппинг процесс → сокет

# Windows
netstat -ano | findstr ESTABLISHED
Get-NetTCPConnection -State Established  # PowerShell
```

Они отвечают «какие соединения есть сейчас». Но не говорят, какое приложение, где сервер и подозрительно ли это. Именно этот зазор закрывает визуализатор.

## Подход визуализации

Snitch рисует каждое соединение как живой граф + карту мира:

- **Узел = твоя машина** в центре, линии к каждому удалённому endpoint'у
- **Каждый endpoint подписан**: hostname (через reverse DNS + TLS SNI), геолокация страна/город — всё офлайн, из локальной базы MaxMind/DB-IP
- **Привязка к приложению**: соединение рисуется к *процессу*, который его открыл
- **Таймлайн**: объём трафика за 15/30/60 мин, 24 ч истории в локальном SQLite

Чем отличается от tcpdump: данные *уже обработаны*. Не «пакет к 142.250.74.78» — а «Chrome → google.com → Франкфурт».

## Читаем карту: норма и подозрительное

Нормальная карта: лучи к Apple/Google/Microsoft/CDN'ам твоих вкладок, роутеру, другим LAN-устройствам.

Что выделяется:

- **Beaconing** — соединение, срабатывающее через регулярные интервалы (Snitch помечает; классический паттерн C2)
- **Длинные аплоады на незнакомые endpoint'ы** — данные непрерывно уходят туда, где ты их не узнаёшь
- **Port-сканы** — LAN-хост, трогающий много портов твоей машины, помечается
- **Приложения, говорящие со странами**, нелогичными для их функции
- **Трекеры** — Snitch сверяет hostname'ы с редактируемыми списками трекер-суффиксов и учитывает их в privacy score
- **DNS-туннелирование** — DNS-запросы с аномально длинными именами или необычной частотой

Встроенный **детектор аномалий** следит за всем этим автоматически, а тревоги можно глушить по правилам после проверки паттерна.

## Установка (2 минуты)

```bash
# macOS: скачай приложение с releases или brew
# Windows: установи Npcap → запусти snitch-backend.exe от админа
# Linux / Docker:
docker run --network host ghcr.io/aixisstudio/snitch

# Нет прав админа? Демо-режим показывает полный UI с синтетическим трафиком:
SNITCH_DEMO=1 snitch-backend
```

Всё остаётся локально — токен-аутентифицированный API на loopback, ноль телеметрии, без аккаунта, и каждый исходящий вызов (GeoIP, обновления, threat intel, вебхуки) — opt-in. Это не маркетинговая строка; это AGPL-кодовая база, можешь сам проверить сетевой путь.

А когда что-то выглядит плохо — можно действовать: с v1.2 Snitch пушит правила блокировки в нативный фаервол ОС (netsh / iptables / pf), имеет lockdown в один клик, кнопки kill/suspend и форензик-экспорт (JSON/CSV/STIX) для пойманного.
