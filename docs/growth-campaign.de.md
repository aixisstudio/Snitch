> **Ziel: 100–300⭐ in 24h am Tag X → GitHub-Trending-Eintritt → selbstverstärkende Schleife.**
> Goldene Regel: sämtlicher Traffic muss am SELBEN Tag aufs Repo konvergieren. Kanonische Version mit allen Tabellen in `growth-campaign.md` (EN/FR).

## Die 4-Schichten-Strategie

```
Schicht 4 — LONG TAIL (Wochen)       SEO-Artikel, Evergreen-Q&A, Verzeichnisse
Schicht 3 — REKURRENZ-SCHLEIFE       jedes Release = neuer Share-Moment
Schicht 2 — TAG X (Dienstag)         PH + HN-Repost + Reddit + Social, gestapelt
Schicht 1 — KONVERSION (immer an)    Repo konvertiert Besucher → Star
```

## Schicht 1 — Repo-Konversion

Anonymisierte Social Preview, Discussions aktiv + Pinned Post, 20/20 Topics, FUNDING.yml, README in 8 Sprachen + Demo-GIF, subtiler Star-CTA, Awesome-Badge, direkte Download-Links pro OS in den ersten Zeilen.

## Schicht 3 — Rekurrenz

- Jedes Release = Anlass zu posten (v1.x → neue Welle alle 2-3 Wochen)
- Changelog → Cross-Post dev.to/Medium
- Monatlicher « State of Snitch »-Post mit echten Metriken

## Schicht 4 — Long Tail

- SEO-Artikel aus `docs/articles/` (GlassWire/Little-Snitch-Alternativen) auf dev.to/Medium
- StackExchange/Quora-Antworten « how to see what my PC connects to »
- Verzeichnisse: AlternativeTo, SaaSHub, LibHunt, Awesome-Listen
- Lokalisierte Communities: Qiita/Zenn (JP), V2EX/Juejin (CN), dev.to ES/PT
