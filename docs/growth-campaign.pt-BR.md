[English](growth-campaign.md) | [Français](growth-campaign.md) | [Español](growth-campaign.es.md) | [Deutsch](growth-campaign.de.md) | [Русский](growth-campaign.ru.md) | [日本語](growth-campaign.ja.md) | **Português** | [中文](growth-campaign.zh-CN.md)

> **Objetivo: 100–300⭐ em 24h no dia D → entrada no GitHub Trending → loop autoalimentado.**
> Regra de ouro: todo o tráfego deve convergir no MESMO dia para o repo. Versão canônica com todas as tabelas em `growth-campaign.md` (EN/FR).

## A estratégia em 4 camadas

```
Camada 4 — CAUDA LONGA (semanas)    artigos SEO, Q&A evergreen, diretórios
Camada 3 — LOOP DE RECORRÊNCIA      cada release = novo momento de compartilhar
Camada 2 — DIA D (terça)            PH + repost HN + Reddit + social, tudo empilhado
Camada 1 — CONVERSÃO (sempre on)    repo que converte visitante → star
```

## Camada 1 — Conversão do repo

Social preview anonimizada, Discussions ativadas + post fixado, 20/20 topics, FUNDING.yml, README em 8 idiomas + GIF demo, CTA star sutil, badge awesome, links de download direto por OS nas primeiras linhas.

## Camada 3 — Recorrência

- Cada release = desculpa pra postar (v1.x → nova onda a cada 2-3 semanas)
- Changelog → cross-post dev.to/Medium
- Post mensal « State of Snitch » com métricas reais

## Camada 4 — Cauda longa

- Artigos SEO de `docs/articles/` (alternativas GlassWire/Little Snitch) no dev.to/Medium
- Respostas StackExchange/Quora « how to see what my PC connects to »
- Diretórios: AlternativeTo, SaaSHub, LibHunt, listas awesome
- Comunidades localizadas: Qiita/Zenn (JP), V2EX/Juejin (CN), dev.to ES/PT
