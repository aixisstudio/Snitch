## 💭 На рассмотрении

- Пользовательские правила тревог в UI
- Опциональное удалённое сопряжение для headless-хостов — с согласием и токеном
- Слои карты: вид ASN / организация
- Импорт блоклистов (StevenBlack hosts, EasyList) — требует проверки приватности/лицензий
- Профили фаервола (строгий/поездка vs разработчик/пермиссивный)

## 🔬 Исследования — задокументировано, не реализовано

Идеи, которые привели бы Snitch к десктопному EDR/XDR. Перечислены честно —
**ничего из этого не реализовано**; каждое требует своего дизайна, нативных
компонентов и часто второго бинарного артефакта:

- **Пробы eBPF (Linux)** — захват `sys_enter_connect`/`accept` в kernel-space, устойчивый к обходу; нужен скомпилированный BPF-модуль + root
- **WFP callout (Windows)** — настоящая фильтрация в ядре вместо оркестрации `netsh`; нужен подписанный драйвер
- **NetworkExtension (macOS)** — `NEFilterProvider` для фильтрации по bundle; нужны Apple Developer ID + entitlements
- **Корреляция память/поток** — инспекция неподписанных DLL / регионов `PAGE_EXECUTE_READWRITE` на фоне подозрительных соединений
- **Dynamic Taint Analysis** — доказать эксфильтрацию побайтово; тяжёлое исследование
- **Локальная SecOps SLM** — модель 1–3 млрд параметров, объясняющая тревоги на естественном языке
- **Флит-интел через ZKP** — делиться детекциями между узлами, не раскрывая endpoints
- **Счётчики PMU/железа** — признаки ransomware ниже ОС (спекуляция, всплески крипто)
- **Merkle-целостность загруженных модулей** — ловить пропатченные DLL до первого пакета
- **Sinkholing / микро-контейнмент** — перенаправлять подозрительный поток в локальный honeypot вместо убийства
- **Экспорт PCAP** остаётся в скоупе выше

## 🚫 Вне области

Сознательно, по дизайну:

- **Телеметрия, аналитика, аккаунты, облачная синхронизация** — никогда.
- **Пассивный IDS на весь сегмент** — Snitch наблюдает *эту* машину, а не всю сеть.
- **Фильтрация пакетов в user-space** — блокировка делегируется нативному фаерволу ОС (или будущим компонентам ядра), никогда не реализуется заново.
